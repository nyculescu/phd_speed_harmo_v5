## Lens: Bidirectional check (down / up / collide)

**Summary.** Down vs Up collisions. (1) Down, from D5.8 and CLAUDE.md, asks 'do vanilla DRL, the coordinated arms and the local arms differ only in policy and declared information?'. Up, from the ZoneController interface and the shared-snapshot rule, shows the draft cannot guarantee this. observe() receives the full snapshot (BD-1). Neighbour plans arrive with a 2-s lag for the distributed arms but none for centralized DRL (BD-9). The per-CAV action shape is undecided while the P1 spaces depend on it (BD-2). The draft's stated core property, 'replace one controller without changing the plant', holds for code but not for information. (2) Down, from the method, asks for 'tool checks and an early KILL first'. Up, from 'build on CORR2X' and the P0 order, shows every P0 module tied to an unvalidated, possibly abandoned network before any KILL evidence (BD-4). (3) Down, from B7 'one gate shared by every arm' and Q6 'NC', meets Up from the pipeline stage 'Detect operating regime' inside each controller. Pause semantics and the NC definition are one object, NC actuator defaults, and the draft owns neither (BD-5, BD-6). (4) Down, from 'tuned comparators' and D5.8's headline metric, meets Up from MetricsCollector(snapshot, actions) and ScenarioConfig. Insertion-queue delay is invisible to snapshots (BD-3), and tuning, budgets, seed roles and regimes have no owner (BD-7). The draft is sound on separating plant, policy, bus and evaluation, but it leaves open exactly the contracts the comparison depends on.

**Steelman.** The thing I would reject is §10's order, which builds contracts, the bus and coordinated control before any tool check. Saving it: contract documents cost no CPU. T0 for CAV commands and T1 ('control at one zone changes another') cannot run without most of P0 anyway: a plant adapter, ACT-01, scoped observations and metrics with insertion queues. So building P0 first is partly forced. Following that to the end: the argument holds for T0-CAV and T1, but not for the NC realism gate or the early-KILL check with ALINEA/VSL. The existing corr_run can run both once m_day is reshaped to B12. It turns into a split order: step 0 is NC realism plus the existing conventional arms on CORR2X; steps 1-4 then build only what T0/T1 need; the bus and coordinated control (step 5) wait until T1 shows the zones interact.

**Falsifier.** Whether CORR2X under the B12 morning-peak demand (with the CAV/HDV mix) shows a realistic, artefact-free breakdown at the zipper, and whether any existing tuned arm (corr_run alinea/vslalinea) or oracle beats NC by ≥ 10 % there. If it does not, the early-KILL rule applies and most of the P0 inventory is premature. If it does, BD-4 drops to minor and the rest stand as contract fixes. The measurement has not been run (seeds 7,400,010-099). The author holds the decision to keep CORR2X.

### BD-1: Observation scoping is not enforced, so the local vs coordinated contrast and the vanilla-DRL 'same observations' rule are both unenforced

- Severity: blocker (reviewer) → **major** (verifier); verdict **confirmed**; kind: interface / fairness of arms; needs author decision: no
- Anchor: §4.1 'def observe(self, snapshot, messages)' + §3 step 3 'The controllers receive the same timestamped snapshot' + §6 'StateEstimator +build_zone_observations()'
- Evidence: FACT: the draft gives two owners for one job. StateEstimator.build_zone_observations (§6, §5 step G) builds the observations, and ZoneController.observe(snapshot, messages) also 'constructs the controller's observation' from the whole snapshot (§4.1). FACT: design_v0.md:96 says local arm 'Each zone runs alone, with no messages', and line 100 says vanilla DRL uses the 'same actuators and observations'. CLAUDE.md 'Fair vanilla DRL' says 'the same observations'. FACT: §2 feature table promises 'Each zone receives correctly scoped measurements', but no interface carries that scope. INFERENCE: a local controller can read Z2/Z3 fields from the shared snapshot. Then 'Isolates the benefit of communication' (§4.4) no longer measures communication. Nothing records which observation set each arm actually used.
- Recommendation: Make OBS-01 the only owner. It builds a typed ZoneObservation from a declared, per-arm observation spec: local = own zone; coordinated = own zone + bus messages; centralized DRL = concatenation of the same specs. Controllers never receive the raw snapshot. Log a hash of the observation spec per run in the ledger. Add a contract test that a local arm's observation contains no field of another zone.
- Verifier: Checked and holds. The draft has §3 step 2 'The state estimator derives the observations for all three zones', and also step 3 'The controllers receive the same timestamped snapshot', and §4.1 'observe(self, snapshot, messages)'. So two places build the observation, and every controller is handed the whole snapshot. Nothing in the draft limits a local arm to its own zone, yet design_v0.md:96 says the local arm runs 'alone, with no messages' and design_v0.md:100 and CLAUDE.md 'Fair vanilla DRL' require the 'same ... observations'. The draft also steps back from design_v0.md:87, where the interface is ZoneController.act(obs_i, msgs) and already takes a per-zone obs_i. I lowered it from blocker to major: it is a fix to the interface sketch before interfaces.md is written (§10 step 1), and design_v0 already holds the right form, so it does not yet invalidate any comparison.

### BD-3: The data path for the headline metric cannot see insertion queues or desired departure times

- Severity: major (reviewer) → **major** (verifier); verdict **confirmed**; kind: metric definition / gameability; needs author decision: no
- Anchor: §6 'MetricsCollector +record_step(snapshot, actions)' + §1 'PLANT -->|Trajectories / events| MET' (no DEM→MET edge)
- Evidence: FACT: design_v0.md:129-131 makes the headline the door-to-door delay including on-ramp and insertion queues: per vehicle, d2d time minus the free-flow time of its own route. FACT: vsl_lab/jobs/corr_run.py:109-110 computes this from the demand manifest (`for dep, vid, rid, _ in dem.vehicles: ... arrival_t.get(vid, t_censor) - dep`), not from simulator snapshots. Vehicles not yet inserted never appear in a snapshot. FACT: no module in the draft owns the per-route free-flow reference time. corr_run reports d2d time, not delay. INFERENCE: if it is built as drawn, an arm that holds vehicles at insertion lowers measured delay. docs/lessons_metric_gameability.md warns of exactly this gameable metric.
- Recommendation: Add a DEM-01→MET-01 contract: a demand manifest (vid, route, desired departure) plus arrival and censoring events. Put the per-route reference time and the censoring rule in interfaces.md. Add a unit test with a synthetic insertion backlog whose delay is known analytically.
- Verifier: Checked and holds. Metrics in the draft get only plant data: §1 'PLANT -->|Trajectories / events| MET', with no edge from DEM to MET, and §6 'record_step(snapshot, actions)'. MET-01 lists 'queues' and §9 lists 'ramp queues', but the draft never mentions origin or insertion queues, which design_v0.md:129 requires. corr_run.py:109-110 computes d2d time from the demand manifest (dem.vehicles dep → arrival_t), not from snapshots. Its 'delay_vs_ref_s' (corr_run.py:125-127) uses the mean of the first 300-s bin as the reference, not each route's free-flow time, so no existing module owns the reference that design_v0.md:130 requires. docs/lessons_metric_gameability.md:83 names this exact trap: 'TTS gaming via insertion blocking'. One mitigating point: §11 already asks for a gap analysis of existing code, which would find corr_run's approach. The interface itself is still wrong as drawn.

### BD-5: The B7 pause gate sits inside each controller instead of one shared gate, and its actuator semantics are undefined

- Severity: major (reviewer) → **major** (verifier); verdict **confirmed**; kind: fairness of arms / shared rule; needs author decision: yes
- Anchor: §4.3 pipeline stage 'D["Detect operating regime"]' inside each controller + §3 'remain active between updates unless a defined safety or operating rule requires an intervention'

- Verifier: Checked and holds. B7 (design_v0.md:36) requires 'one gate rule shared by every arm' and a pause of learning, inference and activity. B11 (design_v0.md:40) has DRL train on peaks only.
