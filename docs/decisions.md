# v5.B.1 decision log

Author decisions, newest last. "Open" items need the author before they bind. B1–B15 (`docs/v5b/design_v0.md` §2 on
`claude/v5b-core`) are draft inputs until re-confirmed here. Review findings are in `docs/architecture/review_v0.md`.

| # | Date | Decision | Status |
|---|---|---|---|
| V1 | 2026-10-13 | Branch `v5b1`, empty history, is the main branch and the GitHub default (confirmed `origin/HEAD → v5b1`) | decided |
| V2 | 2026-10-13 | The CORR2X network evolves into **F3Z** ("Freeway, 3 zones"). Supersedes the name F4R1M proposed the same day | decided |
| V3 | 2026-10-13 | **Action granularity: per-CAV commands** (accelerate / hold / brake in ±5 km/h steps). Lane/segment-level CAV targets were tried earlier and failed (author's experience, not a re-checked log). Zone-level agents also "almost failed" (author) | decided |
| V4 | 2026-10-13 | **No control (NC):** no speed limit beyond the network maximum, no speed set for any vehicle, **ramp meters off (always green)**. NC is not used in training; it is used in evaluation (the D5.8 denominator, extremes) | decided |
| V5 | 2026-10-13 | **HDV lane limits** as in v5: set the lane's maximum speed; HDVs comply partly (speed-factor spread). Full compliance is not wanted: the noise is part of the problem. **CAVs are kept outside lane limits by speed mode 95** (verified 2026-10-13 in SUMO 1.27.1, single vehicle, lane max 72 km/h: `setSpeed(108)` reaches 72 under the default mode 31, 108 under mode 95; mode 95 kept the safe gap behind a slower leader) | **superseded by V15** (no lane limits); the speed-mode finding is kept for reference |
| V6 | 2026-10-13 | **Invalid run:** more than 2 collisions, or any teleport (> 0). A collision can happen through HDV non-compliance | decided; an invalid run counts as **that arm's failure on that seed** (never dropped for all arms) |
| V7 | 2026-10-13 | **Multi-agent API: PettingZoo.** Direction: **each CAV is an agent** | decided; trainer: see V17 |
| V8 | 2026-10-13 | **No pause gate.** Controllers are always active; they must learn when to start controlling, before the jam forms. (The answers given for a gate: one shared rule, no pause in a full jam, release CAVs / lanes to max / meters green while paused, are kept only in case a gate is reconsidered) | decided |
| V9 | 2026-10-13 | **Retire the word "demand"** in the design: the controller must not be told the inflow; it learns from what it measures | decided; the replacement term is **inflow** (vehicles arriving at the network) |
| V10 | 2026-10-13 | **New metric: energy use** (ICE and electric), including acceleration and braking; the author's most important metric for speed harmonisation. From SUMO if available, else a published model | decided: **energy per vehicle-km per cohort plus the network total** (kWh), with power traces logged for diagnosis; open: the model; its role: see V16 |
| V11 | 2026-10-13 | **Hard braking measured on CAVs** | decided; open: the threshold (3–4 m/s² proposed). HDV hard braking: placeholder only, not measured for now (it cannot be reported in reality) |
| V12 | 2026-10-13 | **No step 0 run now.** Gather information and design first; NC is defined for evaluation later | decided |
| V13 | 2026-10-13 | **Network maximum speed 120 km/h**, a variable that may change later (e.g. 100 km/h) | **superseded by V30** |
| V14 | 2026-10-13 | **Separate Python environments** for v5.B.1 and v6, accepting duplicated disk and memory use | decided |
| V15 | 2026-10-13 | **No variable speed limits and no HDV lane limits.** The system is CAV commands only: CAVs keep a steady speed for the circumstances (fewer decelerations and accelerations) and so steady the traffic around them. A deployed system without VSL gantries is cheaper. HDVs are not measured by the system | decided. **Ramp meters dropped too** (may be added later): CAV commands are the only actuator. Evaluation covers **all vehicles**: HDVs add non-linearity and realism, and harm to them shows in the total cost |
| V16 | 2026-10-13 | **Headline = a mix of energy, delay and CAV hard braking**, designed so that energy cannot be won by slowing traffic: the author's earlier harmonisation results cost the CAVs too much speed. The trade-off is designed in from the start | decided: **form A, generalised cost** (value of time × delay + energy price × kWh + a cost per CAV hard brake, per vehicle-km, over all vehicles); the training reward uses the same mix. Open: the values and their sources, the delay guard x %, the sensitivity rows |
| V17 | 2026-10-13 | **Trainer: our own shared-parameter PPO (CleanRL style) on a standard PettingZoo `ParallelEnv`**, built to be replaceable (`docs/architecture/adr/ADR-001-trainer.md`: contracts, verification ladder, switch triggers, fallbacks RLlib → TorchRL/BenchMARL → SB3+SuperSuit) | decided |
| V18 | 2026-10-13 | **Metric definitions** (cohort, reference time, cut-off, window, stop-and-go) are adjusted after the energy decision | pending V16 |
| V19 | 2026-10-13 | **Comparators:** with no VSL and no meters, the best tuned proven controller for the D5.8 bar is a published **rule-based CAV controller** (e.g. CAV speed harmonisation, jam absorption; candidates from the literature, plus the archived MRG3 staircase / PI rules) | decided; open: which ones (literature check) |
| V20 | 2026-10-13 | **SI units and euro throughout** (km/h, m, s, L, kWh, €); no US customary units | decided |
| V21 | 2026-10-13 | **Energy prices are Irish retail** (author, 2026-10-13): Euro 95 petrol €1.98/L, diesel €2.15/L, household electricity incl. home EV charging €0.4042/kWh. These are among the highest in Europe and are chosen deliberately; they are retail prices incl. taxes (perceived cost), so a lower-price / resource-cost sensitivity row is reported alongside (CLAUDE.md: no proxy headlines) | decided; source: author statement, date of prices to record |
| V22 | 2026-10-13 | **Network inspired by Dublin's M50** | decided; open: consistency with the MnDOT inflow shape, the 120 km/h maximum and US values of time |
| V23 | 2026-10-13 | **Fleet:** CAVs are electric or hybrid; HDVs about 80 % ICE (petrol and diesel mixed in), the rest electrified. In a deployment, CAVs could report their energy over V2X, HDVs cannot: HDV energy is **estimated** with the model, and the report says why | decided; open: exact shares, hybrid model availability in SUMO |
| V24 | 2026-10-13 | **Energy totals per scenario** are reported (whole-scenario kWh and € saved) next to per-vehicle-km values, because under money weights the energy share of the cost is small | decided |
| V25 | 2026-10-13 | **Hard braking is a constraint**, not a priced cost (no accepted price exists; a price made crawling optimal) | decided; open: threshold and tolerance y % |
| V26 | 2026-10-13 | **Command execution:** a CAV command ramps over 2 s with `slowDown(v_target, 2 s)`, then holds `v_target` (a plain `setSpeed` step brakes at the vType decel, about −4.5 m/s², in one step). The same execution layer serves the DRL and every comparator | decided; hold mechanism to verify (slowDown releases to the desired speed after its duration) |
| V27 | 2026-10-13 | **Communication: V2V and V2X** (CAV-to-CAV and zone messages, i.e. infrastructure-side zone units). **No loop detectors** for now | decided; open: whether a CAV's own onboard sensors (speed, radar gap and closing speed to its leader, which may be an HDV) are allowed |
| V28 | 2026-10-13 | **HBEFA4 truck curve** (fuel per km falling with speed) is checked against a second source before trucks enter the reward | checked (`docs/research/truck_energy_check_v0.md`): a fitting artefact (zero v²/v³ terms in most HDV classes); recommended road-load + Willans model for trucks. Author to decide. HBEFA4 has no HEV car class (PHEV pairs only) |
| V29 | 2026-10-13 | **Headline (form A):** generalised cost in € per vehicle-km over all vehicles = value of time × delay + energy price × energy, divided by a **fixed denominator** (the inflow's vehicle-km), ≥ 10 % vs NC under D5.8. Guards: delay not worse than NC by more than x %; hard braking as a constraint (V25). Energy (kWh) and delay are also reported on their own, plus scenario totals (V24) | decided; open: x %, the Irish value of time uplifted to 2026 € (TII PAG growth + CPI) |
| V30 | 2026-10-13 | **Network maximum speed 100 km/h** (as on the M50); still a variable | decided |
| V31 | 2026-10-13 | **Inflow is synthetic.** Sweep a range of inflow levels, then narrow to the band where control is worth it | decided; the narrowing rule must be fixed before data and use non-learning arms only (see protocol) |
| V32 | 2026-10-13 | **Infrastructure comparators (research question):** VSL as on the M50 (eMOS-like) with realistic, low compliance, and **VSL + average-speed (section) cameras** with high compliance. Can they beat the CAV controllers? Author's experience: drivers on the M50 ignore the VSL and stop-and-go waves form (not a re-checked measurement). Our system stays CAV-only (V15) | decided; open: compliance values and their sources |
| V33 | 2026-10-13 | **CAV powertrains:** about 90 % BEV, about 10 % petrol PHEV | decided |
| V34 | 2026-10-13 | **Truck energy:** road-load + Willans model (`docs/research/truck_energy_check_v0.md`); COPERT and the TII OGV fuel function as sensitivity rows; trucks capped at 90 km/h | decided |
| V35 | 2026-10-13 | **HDV hybrids (HEV+PHEV) are modelled as the petrol PHEV pair** (`HBEFA4/PC_PHEV_petrol_Euro-6d_(P)` / `_(El)`); no diesel hybrids. HDV mix from CSO stock (June 2026): diesel 48.7 %, petrol 33.5 %, hybrids 12.9 %, BEV 4.8 % | decided; open: how a PHEV is split between its two modes; truck share |
| V36 | 2026-10-13 | **Agreed:** CAVs get a calibrated ACC base model, and a human-only NC reference row is reported; a command is `slowDown` over 2 s, then `setSpeed` to hold, released (`setSpeed(-1)`) when the CAV leaves the zone; onboard sensors (own speed, radar gap and closing speed to the leader) are allowed; the hard-brake threshold is 3 m/s²; per-km metrics use the fixed denominator | decided |
