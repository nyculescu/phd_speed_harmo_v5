## Open cross-document issues

- KILL criteria still differ by design: #1 KILLs only on a gate that fires decisively and is not underpowered; #2 KILLs on point estimates (K1, K3) after a pre-data power check, and uses a half-width rule for INCONCLUSIVE. Both are now listed in shared §5 as approved protocol rules, so the texts agree, but the two tests do not share one KILL criterion. One rule for both would change substance, so the author decides.
- Changes made in this pass to apply rules the shared document already stated (the author should see them): K2 bands narrowed to [α/2, α+δ] (#1) and [ε/2, ε+δ] (#2), which differs from plan §2/§3 ([α/2, 2α], [ε/2, 2ε]); #1 K3 now needs M to pass A1 in its winning cell; a #1 KILL now also needs decisive firing; #2 A1 uses the larger of the bootstrap and Clopper–Pearson bounds; the #2 harm leg uses the uncorrected 95 % CI (was 97.5 %); #1 gate N2 renamed K4 and its gated-cell count m renamed J; the #2 guarantee wording now applies only in the confirmatory protocol; #2 author time 1.25–2.5 h → 1.75–3.5 h (the plan's separate decisions row); shared §4, §5 and the constants table now point to the protocols' seed lists, group clusters and data locations.
- Power risk for #1: with A1 now required in K3's winning cell, even a perfectly calibrated tracker passes A1 only about half the time at the minimum 1,000 windows per cell and design effect 2 (protocol #1's own figure: n_eff ≈ 2,070 per cell for 80 % over four cells). Expect more INCONCLUSIVE outcomes, each one using the only TGSIM fallback block.
- K2 power for #1: the old example '≈ 4α at N_D' assumed the 2α edge and was removed. My rough arithmetic, not in the documents and not checked by code, puts the upper-side MDE near 3.4α at N_D for the new α+δ edge. That is still above the 3α underpowered limit, so K2 may be underpowered at minimum counts.
- Decisive firing is not spelled out for multi-leg gates (#1 K0 'for every remaining offline arm'; K3's validity, harm and beats legs). Suggested reading: a cell fires decisively if at least one failing leg is decisive there. One sentence is needed before data.
- Opponent sets differ: #1's K3 does not require beating the online global tracker O6 (K4 only requires that O6 and O7 do not beat M), while #2's GO requires beating its online arms O5 and O7. Confirmatory A2 requires beating every A1-valid online opponent, so a #1 GO can still fail A2 on O6.
- The 'no A1-valid opponent' case is handled three ways: the shared claim rule calls it 'validity-only' (no efficiency win); #1 requires beating the remaining (not significantly invalid) offline arms and the placebo, which reduces to the placebo alone if no offline arm remains; #2 sets V(r) = {O4}. Shared §5 now defers to the protocols for kill tests, but in #1 a cell can pass K3 by beating only the placebo.
- #2 now records the validity power per regime in its power-check addendum, but it does not say what happens if this is below 0.80. Shared §5 says pool the cells; #2's GO needs A1 in each of its two regimes.
- Arm IDs and gate numbers are local to each protocol: #1 O7 = rolling quantile, while #2 O7 = online forecaster and O8 = rolling window; headroom is K0 in #1 and K1 in #2, as in the plan. The #1 decision labels D1 and D2 also clash with the D and D0 gates. Not renamed, to avoid new substance.
